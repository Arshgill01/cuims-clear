# 0.8.6 fix checklist

Branch `fix/0.8.6-captcha` (worktree `cuims-clear-0.8.6`), from 0.8.5 (`fix/0.8.5`, fast-forwarded
into `main` first).

## What was wrong

- [x] **The OCR itself.** Tesseract read ~70% of unseen CUIMS captchas (old holdout set). It confused
      case (V/v, S/s, O/0), invented characters on checkerboard/cross-hatch backgrounds, and returned
      3–7 character strings. This is the "one character wrong" and the "completely different string"
      the student sees.
- [x] **Wrong lengths were submitted.** CUIMS captchas are always 4 characters, but the tab
      auto-submitted any 4–6 character read and the background any 4–6 character read: guaranteed
      refusals, each counting towards CUIMS's lockout.
- [x] **The background spent the tab's tries.** The background sign-in records its failures in the
      shared login guard, and the tab counts them in its 3-try budget. Two background misreads left the
      tab one try, then "Auto-login paused".
- [x] **The background and the tab fought over one captcha.** CUIMS keeps one captcha per session and
      both share the cookie jar:
  - Open CUIMS / Open LMS waited 30 s for the background sign-in and then opened the tab anyway,
    *without stopping the sign-in*. Tesseract's cold start in Chrome's offscreen page often took most
    of that, so the tab's login page and the background's submit raced, and each replaced the other's
    captcha;
  - a tab only announced itself after the content script had loaded settings and found the form, after
    its captcha request was already out;
  - the background re-drew up to 3 captchas per sign-in and made up to 2 submits per refresh.
- [x] **Why it "sometimes works like a charm".** With saved report ids, a refresh is one cookie-less
      `GetReport` call with no session at all, so no captcha is involved. Only when the ids stop working
      does the background have to sign in, and that's where all of the above happens.

## What changed

- [x] `captcha-solver.js` + `captcha-glyphs.js` replace Tesseract. CUIMS draws Courier New Bold 20 px,
      4 characters on a 12.25 px pitch from x = 3 (fitted on the corpus, NCC 0.96). Steps:
  1. find the line's offset (±4 px x, ±3 px y);
  2. rank all 62 glyphs per cell (±1 px drift);
  3. judge the top 4 per cell together against the whole image;
  4. settle close calls (1/l, q/g) on only the pixels where the two glyphs differ.

  `confident` gates auto-submit. No WASM, offscreen page, worker or messaging remain, and the
  packages shrink from 7.1 MB to ~300 KB.
- [x] Only confident 4-character reads are auto-submitted (tab and background).
- [x] The tab stamps `tabLoginTouchAt` at `document_start` on `/` and `/Login.aspx`. The background
      treats it like the 8 s heartbeat, and checks again right before submitting (`beforeSubmit`). A
      tab that arrived mid-sign-in makes it give way (`tab-login`) without recording a failure.
- [x] `ensureSession({ signal })`: Open CUIMS/LMS aborts the sign-in when its 30 s wait ends; an
      aborted sign-in never submits.
- [x] Background: one submit per sign-in, one unsure re-draw.
- [x] Tab: a login page restored from history (`back_forward`) or bfcache restarts instead of
      submitting a dead captcha. The captcha's issue time is its own Resource Timing `fetchStart`,
      so a background touch *before* it no longer forces a restart. A failed read no longer
      re-solves in a loop through the page observer.

## Log

- 2026-10-01: Merged `fix/0.8.5` into `main` (fast-forward, local).
- 2026-10-01: Fetched 400 captchas from the live `GenerateCaptcha.aspx` without cookies
  (`work/corpus/live`), 0.4 s apart. All 400 strings are distinct. The old corpus had only 34
  distinct strings across 130 images. Labelled by the template matcher and checked by eye in grids.
- 2026-10-01: Old label `1Ee2` (4 images) is `lEe2`: Courier's `l` has a flat flag, `1` a slanted one.
- 2026-10-01: `1` vs `l` was the only fragile pair (whole-cell margin as low as 0.021). Settling on
  differing pixels raised the smallest real margin to 0.136.
- 2026-10-01: Firefox 14x refuses automated navigation to `moz-extension://` pages, so `e2e-bg.mjs`
  is Chrome-only. Firefox's background path is covered by `solver-browsers.mjs` and
  `tests/firefox-background.test.mjs`.
- 2026-10-01: Firefox e2e harness fixes: an intercepted request that a navigation had already cancelled
  rejected unhandled and killed the run, and a navigation timeout now counts as a miss instead of an
  abort. One earlier non-verbose Firefox run showed one wrong submit out of 280 that two verbose
  reruns of the same 280 did not reproduce (both 280/280). The solver itself is 530/530 in Firefox.
