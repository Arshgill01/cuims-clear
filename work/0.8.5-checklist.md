# 0.8.5 fix checklist

Branch `fix/0.8.5` (worktree `cuims-clear-0.8.5`), from released 0.8.0 (`feat/themes-0.8`).

- [x] **VDL left / "14 duty leave pending"**: CUIMS's "Not Recommend" status was read as pending,
      and every absent mark in those slots was counted as pending leave. "Not Recommend"/"Not Approved"
      now count as refused; VDL left is `10 − VDL column`; counts cached by 0.8.0 are discarded
      (`LEAVES_VERSION` 2) and re-read on the next Refresh.
- [x] **Dark-theme legibility** (white/grey blocks under light text): jQuery UI widgets get their
      colours from classes added after load, which 0.8.0 never re-read. Their texture images are
      dropped too, and `<body>` is painted inline to beat CUIMS's own `body{…!important}`.
- [x] **Sections staying white until the theme is re-applied**: class/style changes, UpdatePanel swaps
      and late stylesheets now repaint the affected subtree, synchronously, before the browser draws.
- [x] **Flash of the default CUIMS look**:
  - the page is held on the theme's canvas until the first paint (2.5 s safety reveal);
  - colour transitions (`transition: all .4s` on CUIMS) no longer fade from white;
  - a theme switch now updates the page's own copy of the choice, so the next load starts right.
- [x] Found along the way:
  - a repaint loop with content.js's overlay check (`classList.remove` on an absent class);
  - layout thrash (one forced layout per element) in 0.8.0's paint;
  - light-theme text on mid-tone fills could miss 4.5:1.
- [x] Tests green (187), Chrome + Firefox harness runs clean, packages built as 0.8.5.
