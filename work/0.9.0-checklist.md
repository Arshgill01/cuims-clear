# 0.9.0 checklist

Branch `feat/0.9.0-layout`, from `main` at 0.8.7 (61664ac).

0.9.0 arrived as two store zips built on 0.8.6, so it lacked 0.8.7's LMS Semester Work fix. Every
shared file was taken from the 0.9.0 zips except `lms-model.js`, which keeps 0.8.7's version (0.9.0
had not touched it). Version stays 0.9.0.

## What 0.9.0 brings

- [x] **Popup layout.** A side rail (Attendance, Login, Theme, Settings) beside a fixed 440×600 pane
      that scrolls inside, instead of one 1400 px column. Attendance opens first once a login is saved;
      a first run opens on Login, with a dot on the rail until a UID is saved.
- [x] **Settings tab.** Every automation, quiet-mode and LMS switch saves as it is flipped; only the
      login has a Save button, enabled only when the fields differ from what is saved. Submit login is
      shown off and disabled while Solve CAPTCHA is off. The Login tab summarises what the login page
      will do. Clear login asks for a second press.
- [x] **Themes.** Seven more (Ristretto, Ethereal, Lumon, Hackerman, Last Horizon, Miasma, Rosé Pine),
      grouped Light / Dark. Twenty in all; every one passes the WCAG contrast test.
- [x] **Quiet mode.** Whole-word keywords ("generating" is not "rating", "prevent" is not "event", the
      queries dialog's `pointer-events` CSS no longer reads as an event); CUIMS's `#loader-wrapper` is
      never hidden as a wash; SweetAlert backdrops around a shown dialog are kept; the mock-test and
      online-test pages are left alone; a dialog the student opens (queries dialog's "Give Rating") is
      left open.
- [x] **LMS.** Switching to the clear view on a page loaded in Original view now reads the courses.
- [x] **Attendance.** A refresh that arrives while an open is running waits for it, then reads.

## Fixed during integration

- [x] **A hidden promo came back on the student's next click.** 0.9.0 allowed any dialog that was
      "shown by the page" within 15 s of a click. A Bootstrap promo hidden on load keeps its `in`
      class, so the next scan after any click re-showed it. The gesture was also carried over in
      sessionStorage to the next page, so typing on the login page let the dashboard's promo through.
      Now a dialog is allowed only if the click came before it first appeared, and a carried-over
      click counts only for the same page (a postback). `tests/quiet-mode.test.mjs` failed 4/18 on
      0.9.0 as shipped and passes now.
- [x] Tests updated for the new popup (`chrome-saved-login`: two-press Clear login; `themes`: twenty).
